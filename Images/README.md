# CAD images and numerical figures

The nine `nodi_*.png` product views are Blender/Cycles renders of the placed STL exports from the final CadQuery assembly. The hero, exploded, orthographic and internal views use the same solids. The internal view hides the base cup/deck and head shell/bezel so the hardware can be inspected; it is not a supported physical configuration. Flexible wires and labels are not modeled.

The OLED artwork is illustrative. The pose GIF holds three discrete postures; it demonstrates character direction without claiming hardware performance or a time-accurate trajectory. Positive pitch rotates about +X and lowers the front face: sleepy +18°, awake 0°, cheerful −12°. The runtime firmware uses its own documented bounded expressive targets.

Rebuild after CAD export, from the repository root:

```bash
for view in hero exploded front side top cutaway sleepy awake cheerful; do
  blender -b --python tools/render_cad.py -- "$view"
done
python tools/package_media.py
```

Use Blender 4.5.3 and the repository Python requirements. The hero Blender scene packs its display texture. [Render provenance](render_provenance.json) records CAD input and image hashes.

`actuator_torque_analysis.png` and `command_motion_profiles.png` are standard Matplotlib numerical figures, regenerated by `python Analysis/plot_analysis.py`, with standalone PDF copies in Analysis. `nodi_yoke_drawing.png` is a preview of the actual drawing PDF; the PDF and editable Python/SVG sources remain authoritative for review. PyMuPDF was used to rasterize that preview.
